# Watch Party — Spec

## 개요

여러 명이 같은 YouTube 영상을 호스트의 재생 제어에 동기화되어 함께 보고 채팅하는 방. 가입 없이 닉네임만으로 즉시 참여하며, 방은 호스트 중심으로 만들어지고 호스트가 떠나면 종료된다.

## 범위

### 포함
- 랜딩 페이지에서 닉네임(+ 선택 초기 YouTube URL) 입력으로 방 생성, 6자리 숫자 방코드 + 공유 링크 발급
- 방코드 또는 공유 링크 + 닉네임으로 viewer 입장
- 호스트의 YouTube URL 교체 (입력 → '적용' 버튼)
- 호스트의 play / pause / seek가 viewer 전원에 반영
- viewer 재생 위치가 host와 ±1초 이상 벌어지면 자동 seek로 동기화
- 텍스트 채팅 (닉네임 + 메시지, 입장 이후 메시지만 노출)
- 방 멤버(닉네임) 목록 표시
- 호스트 이탈 시 30초 grace period 후 방 종료
- viewer가 새로고침/짧은 네트워크 단절 시 브라우저 세션으로 자동 재입장

### 제외
- 회원가입·OAuth·사용 이력 — idea.md `Not Doing`. 익명성과 가벼움이 MVP 차별점
- 공개 방 탐색·방 목록 — 비공개 소규모 컨셉
- 음성/화상 — 텍스트 채팅 + 영상 동기화로 painkiller 가설 먼저 검증
- 호스트 위임·다중 호스트 — 권한 모델 복잡도 회피
- YouTube 외 플랫폼 (Vimeo, Twitch 등) — IFrame Player API 한 종 먼저 검증
- 모바일 최적화 — 데스크탑 크롬 우선
- 채팅 모더레이션·이모티콘 리액션·이전 메시지 백필
- 영상 큐(playlist)·방 비밀번호·강퇴

## 시나리오

### 1. 방 생성

- **Given** 랜딩 페이지에 접속한 사용자
- **When** 닉네임 필드에 `민영`을 입력하고 (선택) 초기 URL 필드에 `https://youtu.be/dQw4w9WgXcQ`를 입력한 뒤 '방 만들기' 버튼을 클릭
- **Then** 방 화면으로 이동하고, 6자리 숫자 방코드(예: `483210`)와 공유 링크가 표시되며, 초기 URL을 입력한 경우 영상이 0초에서 멈춘 상태로 로드된다

성공 기준:
- [ ] 닉네임 + 초기 URL 입력 → '방 만들기' 클릭 시 6자리 숫자 방코드 표시
- [ ] 초기 URL을 비워두고 생성한 경우, 방 화면 영상 영역에 'URL을 입력하세요' 안내 표시
- [ ] 잘못된 형식의 URL(예: `https://example.com/x`)을 입력하고 '방 만들기'를 누르면 '유효하지 않은 YouTube URL' 메시지 표시 및 방 생성 안 됨
- [ ] 닉네임이 비어 있으면 '방 만들기' 버튼이 비활성화

### 2. viewer 입장

- **Given** 호스트가 방코드 `483210`을 가진 방을 열어둔 상태
- **When** 다른 사용자가 랜딩 페이지에서 방코드 `483210`과 닉네임 `철수`를 입력하고 '입장' 버튼을 클릭
- **Then** 해당 사용자가 방 화면으로 이동하고, 멤버 목록에 `철수`가 추가되어 호스트 화면에도 즉시 보이며, 현재 host가 재생 중인 영상을 host와 동일한 위치에서 보기 시작한다

성공 기준:
- [ ] 유효한 방코드 + 닉네임 입력 시 방 화면 진입
- [ ] 멤버 목록에 신규 닉네임이 표시됨 (host 화면에도)
- [ ] 존재하지 않는 방코드(예: `999999`) 입력 시 '방을 찾을 수 없음' 메시지 표시 및 입장 안 됨
- [ ] 정원 10명이 이미 찬 방에 11번째로 입장 시도 시 '방이 가득 찼습니다' 메시지 표시 및 입장 안 됨
- [ ] 공유 링크로 진입하면 방코드는 자동 채워지고 닉네임만 입력하면 됨

### 3. 호스트의 URL 교체

- **Given** 영상을 재생 중인 방 (host 1명 + viewer 2명, 영상 진행 중)
- **When** host가 URL 입력란에 `https://www.youtube.com/watch?v=NEWID123`을 입력하고 '적용' 버튼을 클릭
- **Then** host와 viewer 모두 영상이 새 영상으로 교체되고, 모두 0초 위치에서 멈춤 상태가 된다

성공 기준:
- [ ] '적용' 클릭 시 host와 모든 viewer가 같은 새 영상을 표시
- [ ] 교체 직후 host와 모든 viewer가 0초 위치, 멈춤 상태
- [ ] '적용'을 누르기 전 입력란에 타이핑 중인 동안에는 viewer에 변화 없음
- [ ] 잘못된 형식의 URL을 입력하고 '적용'을 누르면 host 화면에 '유효하지 않은 YouTube URL' 메시지 표시 및 영상 교체 안 됨

### 4. 재생 제어 동기화 (play / pause / seek)

- **Given** 같은 영상을 host와 viewer 2명이 동시에 보고 있는 상태 (모두 12초 위치, 멈춤)
- **When** host가 play 버튼을 누른다 (또는 pause, 또는 30초로 seek)
- **Then** viewer 2명의 영상도 동일하게 play된다 (또는 pause, 또는 30초로 점프)

성공 기준:
- [ ] host play → viewer 영상도 평균 300ms 이내 play 상태로 전환
- [ ] host pause → viewer 영상도 평균 300ms 이내 pause 상태로 전환
- [ ] host가 60초로 seek → viewer 영상도 60초로 점프
- [ ] viewer가 자신의 player 컨트롤로 play/pause/seek 해도 다른 멤버에 영향을 주지 않으며, 본인 화면도 곧 host 상태로 되돌아온다

### 5. 드리프트 자동 보정

- **Given** host가 영상을 10초 위치에서 재생 중이고, viewer 한 명의 player가 네트워크 지연으로 13초 위치까지 앞서간 상태
- **When** 시스템이 주기적으로 host와 viewer의 위치 차이를 확인
- **Then** viewer의 영상이 host 위치로 자동 seek 되어 차이가 ±1초 이내로 좁혀진다 (별도 안내 UI 없이 조용히 보정)

성공 기준:
- [ ] viewer가 host와 ±1초 이상 차이 나는 상태가 감지되면 viewer player가 host 위치로 자동 seek
- [ ] 보정 동안 viewer 화면에 추가 메시지/스피너 표시 없음 (단순 점프)
- [ ] 보정 후 ±1초 이내로 들어옴

### 6. 채팅

- **Given** host와 viewer 2명이 방에 있는 상태
- **When** viewer 한 명(`철수`)이 채팅 입력란에 `안녕`을 입력하고 전송
- **Then** host와 모든 viewer의 채팅 영역에 `철수: 안녕`이 표시된다

성공 기준:
- [ ] 메시지 전송 시 방 안의 모든 멤버 화면에 평균 300ms 이내 표시
- [ ] 빈 메시지는 전송 불가 (전송 버튼 비활성화 또는 무시)
- [ ] 메시지에는 발신자 닉네임이 함께 표시됨
- [ ] 채팅이 발생한 후 들어온 신규 viewer에게는 입장 이전 메시지가 보이지 않는다

### 7. 멤버 목록 (presence)

- **Given** host와 viewer 1명이 방에 있는 상태
- **When** 다른 viewer가 방에 입장하거나, viewer가 방을 떠난다 (탭 닫기)
- **Then** 남아 있는 모든 멤버 화면의 멤버 목록이 즉시 업데이트된다

성공 기준:
- [ ] 새 viewer 입장 시 멤버 목록에 닉네임 추가
- [ ] viewer 이탈 시 멤버 목록에서 닉네임 제거 (수 초 이내)
- [ ] 호스트는 멤버 목록에서 호스트임을 구분할 수 있는 시각적 표시(예: 라벨/배지)를 가진다

### 8. 호스트 이탈

- **Given** host와 viewer 2명이 방에 있는 상태
- **When** host가 탭을 닫거나 네트워크가 끊긴다
- **Then** viewer 화면에 '호스트 연결이 끊겼습니다…' 같은 상태 표시가 나타나고, 30초 내에 host가 돌아오지 않으면 viewer 전원이 '방이 종료되었습니다' 화면으로 이동한다 (랜딩 페이지로 돌아갈 수 있는 버튼 포함)

성공 기준:
- [ ] host 이탈 감지 즉시 viewer 화면에 일시적인 안내 표시
- [ ] host가 30초 안에 돌아오면 안내가 사라지고 정상 시청 재개
- [ ] host가 30초 안에 돌아오지 않으면 viewer 전원이 종료 화면으로 이동
- [ ] 종료된 방의 방코드로 다시 입장 시도 시 '방을 찾을 수 없음' 메시지

### 9. viewer 재접속

- **Given** viewer가 방에 입장해 있는 상태에서 새로고침 또는 짧은(30초 미만) 네트워크 단절 발생
- **When** 브라우저가 다시 페이지를 로드하거나 네트워크가 복구된다
- **Then** viewer는 같은 닉네임으로 같은 방에 자동으로 재입장되어 현재 host 재생 위치에서 시청을 이어간다 (재입력 폼 없음)

성공 기준:
- [ ] 새로고침 직후 별도 입력 없이 방 화면 진입
- [ ] 재입장한 viewer는 host의 현재 재생 위치에 맞춰 동기화됨
- [ ] 재입장한 viewer는 끊긴 동안의 채팅 메시지를 보지 못한다 (입장 이전 메시지 미노출 규칙)
- [ ] 단절 시간이 길어 방이 종료된 경우, 새로고침 후에는 '방을 찾을 수 없음' 또는 종료 화면으로 안내

## 불변 규칙

### 권한
- play / pause / seek / URL 변경은 host만 발신할 수 있다. viewer가 자신의 player를 조작해도 다른 멤버에는 전파되지 않으며, 본인 화면도 곧 host 상태로 되돌아온다
- 방 안에는 항상 정확히 1명의 host가 존재한다 (호스트 이양 없음)

### 데이터 휘발성
- 방이 종료되면 채팅 메시지, 재생 상태, 멤버 정보가 모두 사라진다. 이전 방 기록을 다시 보는 경로는 없다

### 동기화 체감
- host의 play / pause / seek / URL 적용 / 채팅 메시지는 viewer에 평균 300ms 이내 반영
- viewer가 host와 ±1초 이상 어긋나면 자동 보정으로 ±1초 이내로 들어온다

### 입력 제약
- 닉네임: 1-20자, 중복 허용 (같은 닉네임이 한 방에 둘 이상 있을 수 있음)
- 방 정원: 최대 10명 (host 포함). 초과 입장 시도는 거부
- YouTube URL: `https://www.youtube.com/watch?v=<videoId>` 또는 `https://youtu.be/<videoId>` 형식만 허용. 그 외 형식(embed, shorts, 타임스탬프 파라미터 등)은 '유효하지 않은 URL'로 처리

- Supabase Realtime (외부 서비스, 방·채팅·재생 상태 broadcast 및 presence)
